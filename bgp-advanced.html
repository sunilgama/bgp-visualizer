    Concept cheat sheet

    One paragraph per topic. Each is animated in the scenario named in brackets.

    Route reflector (RFC 4456) [1]. Lets an iBGP router re-advertise routes learned from iBGP peers. Clients peer only with the RR. It adds ORIGINATOR_ID and CLUSTER_LIST to prevent loops.

    Confederation (RFC 5065) [2]. Splits one AS into member ASes. Between members, confed-eBGP uses AS_CONFED_SEQUENCE; LOCAL_PREF, NEXT_HOP and MED survive. Outside, only the confederation identifier shows.

    AS_PATH loop prevention (RFC 4271 section 9.1.2) [3]. A router discards a route whose AS_PATH contains its own AS.

    Path selection (RFC 4271 section 9.1) [4]. Order used here: Weight (vendor, local) → highest LOCAL_PREF → shortest AS_PATH → lowest ORIGIN → lowest MED (same neighbour AS) → eBGP over iBGP → lowest IGP metric → router ID.

    Route flap damping (RFC 2439, revised view in RFC 7196) [5]. A penalty rises with each flap and decays with a half-life. Above the suppress limit the route is ignored until it falls below the reuse limit.

    MPLS L3VPN (RFC 4364) [6]. Customers get VRFs on PEs. MP-BGP carries their routes between PEs with a VPN label. The core uses only transport labels.

    Route Distinguisher (RD). 8 bytes prepended to an IPv4 prefix to make a unique VPN-IPv4 route, so overlapping customer prefixes do not collide. It does not control who receives the route.

    Route Target (RT). An extended community that controls import and export between VRFs. This is what builds the VPN topology.

    MP-BGP VPNv4 (RFC 4760). Uses MP_REACH_NLRI with AFI 1, SAFI 128.

    EVPN (RFC 7432, RFC 9136) [7]. MP-BGP with AFI 25, SAFI 70. Type 1: Ethernet auto-discovery. Type 2: MAC/IP. Type 3: inclusive multicast (BUM). Type 4: Ethernet segment. Type 5: IP prefix.

    Simplifications: only fields needed for learning are shown. Timers and times are compressed. Vendor defaults (Weight, damping parameters) vary. Addresses, labels and AS numbers are examples.
