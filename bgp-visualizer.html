    Protocol overview

    BGP (Border Gateway Protocol, version 4, RFC 4271) is the routing protocol that connects independent networks, called Autonomous Systems (AS), on the Internet. Each AS has a number. Two routers that exchange routes are neighbours (peers). BGP does not discover neighbours: you configure them. It runs on TCP port 179, so TCP handles reliable delivery, and BGP itself only needs to decide which routes to tell and which to believe.

    An eBGP session connects different ASes. An iBGP session connects routers inside the same AS. This page shows eBGP.

    Packet flow summary

    1. TCP three-way handshake to port 179 (SYN, SYN+ACK, ACK).
    2. Both sides send OPEN: version, AS, Hold Time, router ID.
    3. Both validate the OPEN, negotiate the Hold Time, send KEEPALIVE.
    4. On receiving KEEPALIVE the session is Established.
    5. UPDATE messages announce or withdraw prefixes.
    6. KEEPALIVEs keep the session alive. Silence longer than the Hold Time, or any error, produces a NOTIFICATION and the session closes.

    Key messages (RFC 4271 section 4)

    TypePurpose
    OPEN (1)Introduces the sender: version, AS number, Hold Time, BGP Identifier, optional capabilities.
    UPDATE (2)Announces routes (NLRI with path attributes) and/or withdraws routes.
    NOTIFICATION (3)Reports an error. The session is closed right after.
    KEEPALIVE (4)19 bytes, header only. Confirms an OPEN, and proves liveness afterwards.

    Timers (RFC 4271 section 10)

    TimerSuggestedMeaning
    ConnectRetryTimer120 sWait before trying TCP again.
    HoldTimer90 sMaximum silence. Negotiated as the smaller of both OPEN values (0 or at least 3 s).
    KeepaliveTimerHold / 3Interval between KEEPALIVEs.

    Finite state machine (RFC 4271 section 8)

    StateMeaning
    IdleRefuses connections, holds no resources. Waits for a start event.
    ConnectWaiting for the outgoing TCP connection to complete.
    ActiveListening for an incoming TCP connection, or waiting to retry after a failed attempt.
    OpenSentTCP is up and our OPEN was sent. Waiting for the peer’s OPEN.
    OpenConfirmPeer’s OPEN accepted. Waiting for its KEEPALIVE.
    EstablishedSession is up. UPDATE, KEEPALIVE and NOTIFICATION may be exchanged.

    Assumptions and simplifications

    • RFC 4271 behaviour is shown. Extensions are not: multiprotocol BGP (RFC 4760), 4-byte AS numbers (RFC 6793), route refresh and graceful restart. OPEN messages are drawn without optional parameters. Real routers send capabilities, which makes the OPEN longer than 29 bytes.
    • The optional DelayOpen and IdleHold timers, the connection collision rules (section 6.8) and route flap damping are not shown.
    • Route selection is reduced to a single candidate. The full decision process (section 9.1) compares LOCAL_PREF, AS_PATH length, ORIGIN, MED and more.
    • Time-lapse steps compress seconds into a few animated seconds. TCP sequence numbers are only shown on handshake segments. The IP and TCP details in the inspector are typical values, not captured data.
    • Router R1 always opens the TCP connection, so it uses an ephemeral source port. Routing policy, authentication (TCP-AO, MD5) and eBGP TTL checks are not shown.
